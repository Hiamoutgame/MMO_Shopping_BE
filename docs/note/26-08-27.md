## Backend - System Module

Hoàn thiện **System Module** cho Shopping V1, tập trung vào read endpoint cho admin và hạ tầng idempotency/outbox/audit.

### Endpoint admin mới

- `GET /api/v1/admin/dashboard/overview` - tổng quan hệ thống (`last24Hours` / `last30Days` / `current`).
- `GET /api/v1/admin/reports/summary` - báo cáo doanh thu, order, user, inventory, view, support-code theo khoảng thời gian.
- `GET /api/v1/admin/audit-logs` - liệt kê audit log thay đổi admin, hỗ trợ pagination và filter.
- Cả 3 endpoint đều dùng `JwtAuthGuard` + `RolesGuard` + `@Roles('ADMIN')`.
- Response trả về theo envelope chuẩn của API.

### File code mới và thay đổi chính

- `src/modules/system/dto/report-query.dto.ts`
- `src/modules/system/dto/audit-log-query.dto.ts`
- `src/modules/system/report-period.ts` - chuẩn hóa khoảng thời gian báo cáo.
- `src/modules/system/report-metrics.ts` - `zeroFill` + `computeNetRevenue`, helper thuần và dễ unit test.
- `src/modules/system/services/system-query.service.ts` - read query cho report/dashboard/audit-log.
- `src/modules/system/services/outbox.service.ts` - `OutboxService.enqueue()` ghi event trong transaction.
- `src/modules/system/controllers/admin-system.controller.ts`
- `src/common/utils/stable-stringify.ts` - hash canonical theo thứ tự key, dùng chung cho idempotency và outbox.

### Hạ tầng harden

- **Idempotency**: thêm kiểm tra **account ownership**. Cùng key/hash nhưng khác account sẽ conflict, không replay response của user khác. Hash đã ổn định hơn, replay chỉ khi record ở trạng thái `COMPLETED`.
- **Outbox**: `enqueue()` ghi `OutboxEvent` trạng thái `PENDING` trong transaction. Có dedup theo `idempotencyKey`: cùng content trả lại event cũ, khác content thì conflict. Hiện **chưa** có worker/scheduler/HTTP dispatch.
- **Audit**: `metadata` được chạy lại `redactSecrets` khi đọc. Nếu `actor` bị soft-delete thì trả `null`.
- **Migration**: `...AddSystemQueryIndexes.ts` thêm 5 index trên các cột thời gian: order `placedAt`, user `createdAt`, product view `viewedAt`, support-code `submittedAt`, audit `createdAt`.

## Ghi nhớ kỹ thuật

### Reporting và System Module

- `revenue.gross` = tổng `totalAmount` của đơn có `paymentStatus ∈ {PAID, REFUNDED}`.
- `revenue.refunded` = tổng `refundedAmount`.
- `revenue.net = gross - refunded`.
- Tiền luôn là decimal string.
- Timestamp theo entity:
  - Order dùng `placedAt`.
  - User dùng `createdAt`.
  - Product view dùng `viewedAt`.
  - Support-code dùng `submittedAt`.
- Khoảng thời gian dùng dạng `[from, to)`.
- Breakdown luôn zero-fill đủ mọi enum.
- `users.total` và inventory là snapshot hiện tại.
- `from`/`to` dùng ISO 8601.
- `timezone` mặc định là `Asia/Ho_Chi_Minh`.
- Thiếu cả `from` và `to` thì mặc định 30 ngày gần nhất.
- Chỉ có `from` thì `to=now`.
- Chỉ có `to` thì `from=to-30d`.
- `to<=from` trả `400 INVALID_REPORT_PERIOD`.
- e2e tạo `AuthSession` và `jwtService.signAsync({subject,email,role,sessionId})` để có token hợp lệ cho guard.
- Cần PostgreSQL để chạy `test:e2e`.

### Frontend API integration

- `GET /products/{id}` hiện trả `variants` cho mọi caller public, khác với admin variant endpoint.
- Frontend dùng `variants` để hiển thị "Chọn gói" và giữ `productVariantId`.
- Money luôn là decimal string ở transport/domain.
- `useCartStore.getTotalPrice` và `CartLineItem` hiện tạm dùng `Number()` cho draft cart.
- Add-to-cart ở `ProductDetailPage` vẫn ghi draft cart bằng `addToCart(product, quantity)`.
- Giai đoạn 3 mới chuyển sang gọi `POST /cart/items` với `productVariantId`.
