- Thêm `RequireAdmin` để bảo vệ toàn bộ route quản trị:
  - Guest được chuyển tới `/login?returnTo=...`.

  - `/admin/finance` - payment transaction và wallet ledger.
  - `/admin/audit-logs` - audit log.
- Các page được lazy-load qua `routes/lazyComponents.ts` và bọc `RequireAdmin` + `AdminLayout` tại `routes/index.tsx`.

### 4. Sửa lint và vòng đời request của admin page

- Lỗi `react-hooks/set-state-in-effect` xuất phát từ việc gọi đồng bộ `setLoading(true)` và `setError(null)` ngay trong effect của các page admin.
- Thêm hook `useAdminRequestState()` với `beginRequest()`, `reload()` và `reloadKey`.
- Loading/error được bật trước khi đổi dependency reload/filter; effect chỉ thực hiện request và cập nhật state trong callback bất đồng bộ.
- Thay đổi ảnh hưởng tới 8 page admin, đặc biệt flow load danh sách, đổi filter, chuyển trang, retry và refresh dữ liệu sau mutation.
- Giữ cờ `cancelled` trong effect để tránh cập nhật state sau khi page unmount hoặc dependency đổi.

### 5. Sửa luồng đăng nhập và khôi phục session cho admin

- `useAuthStore.setUser()` giờ đặt đồng thời `isAuthenticated: true`; session restore không còn có user nhưng vẫn bị coi là chưa đăng nhập.
- `LoginPage` và `RegisterPage` chọn route mặc định theo role:
  - `admin` → `/admin`.
  - `user` → `/products`.

- `useSessionRestore()` tự chuyển admin từ `/`, `/products`, `/login` hoặc `/register` sang `/admin` sau khi `/auth/me` khôi phục phiên.
- Header public hiển thị nút `Admin` khi user hiện tại có role admin.
- Thêm `APP_CONSTANTS.ROUTES.ADMIN` để dùng route gốc quản trị thống nhất.
